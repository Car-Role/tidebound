# WP14 server -> client needs

Server changes that have a client side. The server already tolerates the client doing nothing (all of these are additive).

1. **Hats** (client note "Needs" #2). New action `cosmetic.equip { id }` (id = an unlocked hat cosmetic `cos_d_*` from a Craft or Explore deed, or `null` to take it off). It sets the public player entity key `hat` (the drawer already reads it) and `self.deeds.hat`. Client: a "Wear" button next to unlocked hat cosmetics in the Logbook panel, `send('cosmetic.equip', { id })`.
2. **Keepsake (Moon Chart `moon_keep`)**. New action `moon.keep { ids: [cardId, ...] }` (priority order, max 8). On the next Turning the player keeps `rank` of these cards (else the highest-ranked cards). Client: in the Moon Chart panel, when `moon_keep` rank > 0, let the player tick cards from `self.cards.owned`.
3. **Market selling is gated by Beacon 1** (BUILD_REVIEW P1-2). `market.sell` before Beacon 1 answers `{ ok:false, err:'locked', d:{ why:'Traders buy once Beacon 1 is lit' } }`. Client: show `d.why` as the toast; optionally grey out the Sell tab while `world.unlocks['beacon:1']` is not set.
4. **/unbind** (P0-5). `coop.unbind` on an online player or within 6 h of world playtime of the last unbind now fails (`denied` / `cooldown`) and the host gets a toast with the reason. The `world.coop.S` value is now `|bound UNION online|`, so the crew panel can show S = players online immediately.
5. **Shallows Walker** (`player.walkShallows`): the server now lets the player walk on shallow water while the e12 effect is active. Client prediction (`shared/rules/movement.js` is shared; the client calls `step` with its own walkable function) should treat `T.SHALLOW` as walkable while the local player has the buff, otherwise it rubber-bands at the shoreline. The server does not publish the expiry; simplest: publish a `self.walkShallows` flag (server change, ask WP14) or check the `shallows_walk` proc in the card list.
6. **Trench start at floor 10** (P2-10). `dungeon.enter { id, start: 10 }` at the Trench entrance starts at floor 10 once floor 10 was reached in the world (`world.unlocks['trench:10']`); costs one `vault_key_6` unless the party has Morrow's `trench_no_key` flag. Client: a second button "Dive to floor 10" in the Trench entrance prompt.
7. **Tide Board** (P2-5): one shared set of 3 contracts every 3 in-game days; a contract pays once per world. `board.day` is now the first day of the period. When another crew member turns in a contract you hold, it is removed and you get a toast. No client change needed beyond copy ("refreshes every 3 days").
8. **Tutorial per player** (P2-20) is client-side state; nothing on the server.
